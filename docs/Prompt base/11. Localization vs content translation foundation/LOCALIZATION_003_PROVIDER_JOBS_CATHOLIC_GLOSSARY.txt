JOB IDEMPOTENCY
---------------
Semantic key:
resource + targetLocale + sourceContentHash + provider

Do not duplicate work for unchanged source.

Strong behavior:
- current APPROVED revision for same hash/target => no new job
- current MACHINE_TRANSLATED revision for same hash/target => no duplicate provider work
- existing active job => return existing job
- FAILED/DEAD requeue only through explicit retry method

Use a robust DB uniqueness strategy.

JOB PROCESSOR
-------------
Flow:
1 claim due QUEUED job transactionally
2 mark PROCESSING
3 resolve source snapshot through registry
4 verify current source hash == job hash
5 extract units
6 resolve current published glossary for locale pair
7 provider.translateBatch
8 validate returned IDs/count
9 adapter builds payload
10 create MACHINE_TRANSLATED revision
11 mark SUCCEEDED
12 errors:
   retryable -> FAILED/queued with next_attempt_at
   nonretryable or exhausted -> DEAD

Do NOT auto-APPROVE.

SOURCE CHANGED
--------------
If current source hash != queued hash:
do not translate.
Mark nonretryable terminal state with SOURCE_CHANGED.
Admin queues new job later.

RETRY POLICY
------------
Default max attempts 3 unless project config convention suggests another bounded value.

Retryable:
timeout
429/rate limit
5xx/unavailable

Nonretryable:
source changed
invalid resource
unsupported resource
invalid locale
payload invalid
provider output invalid

Use bounded backoff via next_attempt_at.
