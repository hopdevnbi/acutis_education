PRACTICE VS EXAM — CRITICAL
---------------------------
Practice:
- formative
- retry/review wrong allowed
- immediate correctness can be allowed
- flexible generation
- progress tracking

Exam:
- formal/high stakes
- stricter snapshot/timing/submission
- delayed feedback policy
- separate attempt model

Never reuse Practice attempt tables for Exam.

CONCURRENCY
-----------
Answer attemptNumber must be transaction-safe.
Lock sessionQuestion row or equivalent.

SCORING
-------
Need explicit semantics.

Recommended MVP:
- per attempt score = 0|1 from Question Bank
- session final score = latest/final correctness per question
- firstAttemptCorrectCount tracked/derived separately
- no partial credit
- no mastery score yet

Progress metrics:
firstAttemptAccuracy
finalAccuracy

Do not call either "mastery".

RETRY POLICY
------------
Audit product-friendly MVP.

Recommended simple policy:
- immediate isCorrect returned
- wrong answer may retry
- correct answer/explanation reveal only after final attempt or session completion
- exact retry count should be explicit

Potential config:
maxAttemptsPerQuestion

Avoid large configurable policy system in MVP.

Report must choose exact default and whether stored on session.

REVIEW WRONG
------------
Strong recommendation:
create a new REVIEW_WRONG child session from completed STANDARD session.

Why:
- original completion stays immutable
- separate attempt history
- easy repeated review
- clean metrics

Review session:
sourceSessionId
exact wrong questionVersionIds
no fresh Question Bank selection

If no wrong questions:
PRACTICE_NO_WRONG_QUESTIONS.

Prefer auto-complete when every session question reaches final answered state.

Resume IN_PROGRESS by reloading persisted session/order/attempts.

ABANDONED is soft lifecycle; no hard delete.
