20. Session Generation Transaction
----------------------------------
Use single DB transaction for Practice-owned rows.

Flow:
1. authorize enrollment context
2. resolve assigned curriculum and validate filters
3. check idempotent clientRequestId
4. request exact current-published candidates from QuestionBankService
5. fetch learner projections for selected versions
6. precompute question order
7. precompute delivered option order
8. BEGIN Practice DB transaction
9. insert practice_session
10. insert practice_session_questions
11. commit
12. return session snapshot

Important:
Question Bank calls happen before Practice transaction if they are read-only and transaction cannot span module/service repositories cleanly.

If failure before transaction -> no rows.
If DB insertion fails -> rollback.

21. Generation Idempotency
--------------------------
