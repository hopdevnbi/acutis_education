SESSION/QUESTION FLOW
---------------------
1. load session
2. authorize against enrollment
3. assert sessionQuestion belongs exact session
4. assert session IN_PROGRESS
5. resolve idempotent replay if clientAnswerId exists
6. derive current attempt state

9. persist attempt
10. derive question finalization

12. return answer result

Never resolve root.currentPublishedVersionId.

ATTEMPT TRANSACTION / LOCKING
-----------------------------
Correctness is more important than premature distributed optimization.

Use a transaction with a pessimistic write lock on the practice session and/or session question so:
- attemptNumber is serialized
- max attempts cannot be exceeded concurrently
- session completion cannot race
- duplicate clientAnswerId resolves safely

Question Bank grading is read-only local service today. Calling it while holding the local transaction is acceptable for MVP if needed for correctness, but document that future microservice extraction should use shorter lock/recheck or reservation semantics.

DB unique constraints remain final guards:
- (sessionQuestionId, clientAnswerId)
- (sessionQuestionId, attemptNumber)
