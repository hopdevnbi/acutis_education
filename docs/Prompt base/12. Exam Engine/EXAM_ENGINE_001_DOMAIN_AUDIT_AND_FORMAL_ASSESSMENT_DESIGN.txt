CORE DOMAIN DISTINCTION — EXAM != PRACTICE
------------------------------------------
Practice:
- learning-oriented
- retry per question
- immediate/terminal feedback
- review wrong
- flexible session generation
- accuracy/progress dimensions

Exam:
- formal assessment
- controlled attempt
- fixed question snapshot
- no per-question correctness feedback during active attempt
- answers may be editable before submit
- final submission boundary
- attempt/time constraints
- formal score/result
- review/reveal policy controlled by exam configuration
- auditable snapshot

Do NOT implement Exam by copying Practice semantics blindly.

EXAM BOUNDED CONTEXT
--------------------
Exam should likely own:
- exam definitions
- exam versions/configuration
- exam assignments
- exam attempts
- attempt question snapshots
- attempt answers
- result/finalization metadata

Question Bank remains owner:
- question roots
- question versions
- options
- correctness
- grading service
- source content
- localization source hash

Localization remains owner:
- translation revisions
- locale resolution
- localized question display

Learning Progress remains owner:
- cross-learning read model
- later Exam dimension integration only through Exam public service

Do not cross-own.

ONE ACTIVE ATTEMPT
------------------
Strong recommendation:
max one IN_PROGRESS attempt per enrollment + assignment.

Concurrent starts must be idempotent/rejected safely.

START IDEMPOTENCY
-----------------
Use clientRequestId UUID.

Same requestId/same semantics -> same attempt.
Same requestId/conflicting semantics -> 409.

TIME EXPIRY
-----------
Design correctness without requiring a background scheduler.

Potential:
- every mutation checks deadline
- expired attempt is finalized/autosubmitted using saved answers
- GET may trigger safe lazy finalization if needed

Audit exact transaction model.

ANSWER MODEL
------------
Exam differs from Practice.

Need decide:
- one current answer overwritten until submit
- immutable answer revision history

Formal audit may favor revision history.
Mobile/idempotency may favor clientAnswerId.

Audit best model.

ANSWER SAVE
-----------
No grading feedback while active.

Validate selected option IDs belong pinned question.

Answer may be edited before submit if policy allows.

After submit: immutable.

UNANSWERED QUESTIONS
--------------------
Submission may include unanswered unless product explicitly requires all.

Treat unanswered as zero/incorrect during grading.

SUBMIT / FINALIZE
-----------------
Explicit submit should:
- lock attempt
- freeze final saved answers
- grade server-side via QuestionBankService only
- compute result
- persist result snapshot
- mark final state
- be idempotent

No direct correct-answer SQL.

---------------
QuestionBank grading only.

scorePercent

Do not invent weighted scoring without requirement.

PASS / FAIL
-----------
