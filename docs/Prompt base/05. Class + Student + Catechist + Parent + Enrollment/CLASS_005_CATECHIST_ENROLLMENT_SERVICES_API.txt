25. Transfer Preconditions
--------------------------
Transactionally:

1. load source enrollment with appropriate lock
2. require source ACTIVE
3. load target ClassSnapshot via ClassService
4. require target class accepts enrollment
5. require target class parishId == source.parishId
6. require target class academicYearId == source.academicYearId
7. require targetClassId != source.classId
8. transition source -> TRANSFERRED + leftAt=now
9. create new ACTIVE enrollment with target class scope keys
10. return both old/new snapshots or a clear transfer result DTO

Do not allow transfer across academic year.
Do not allow transfer across parish.

New academic year is a new enrollment workflow, not transfer.

26. Transfer Transaction Boundary
---------------------------------
EnrollmentModule owns both enrollment rows, so transaction belongs entirely inside EnrollmentModule.

This is correct.

Cross-module ClassService validation happens before/within operation carefully.

Do not attempt distributed/shared repository transaction with ClassModule.
