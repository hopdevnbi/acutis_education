3. Permanent Architecture Rule
------------------------------
This project is currently a modular monolith, but every business capability must be designed so it can later be extracted into independent microservices with minimal rewriting.

For EVERY decision in this audit:

- identify data ownership
- identify public module contract
- identify inbound dependencies
- identify outbound dependencies
- avoid cross-module repository access
- avoid ORM entities as cross-module contracts
- avoid cyclic dependencies
- avoid giant "shared" business modules
- avoid premature microservice implementation
- preserve scalar IDs/contracts at module boundaries

Do NOT optimize for microservices today at the cost of needless complexity.

The goal is:
clean modular monolith now,
extractable bounded contexts later.
