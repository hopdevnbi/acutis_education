13. One ACTIVE Year Per Parish
------------------------------
CRITICAL rule:

At most one ACTIVE academic year per parish.

When activating:
- ensure target parish ACTIVE
- check no other ACTIVE year exists for same parish
- if one exists and it's not the same row -> reject with domain error

Potential error:
ActiveAcademicYearAlreadyExistsError

This must be race-aware.

14. Race Safety for One ACTIVE Rule
-----------------------------------
Service-level check alone may race.

Audit possible approaches.

Options:
A. filtered unique index on `(parish_id)` where status='ACTIVE'
B. transaction + lock
C. service check only

Since #001 intentionally deferred DB unique active rule, do not casually add index without considering migration.

For current modular monolith:
preferred robust solution:
transaction + appropriate MSSQL lock/serialization on activation path.

If that is too complex/brittle:
document residual race and classify severity.

Do NOT silently claim race-safe if not.

If schema migration is genuinely required:
create a new migration and justify it.
