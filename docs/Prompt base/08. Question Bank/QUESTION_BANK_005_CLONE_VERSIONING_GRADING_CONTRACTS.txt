6. Clone Transaction — CRITICAL
-------------------------------
Use one transaction.

Recommended sequence:
1. lock question root pessimistically
2. load source version
3. assert source belongs root and is PUBLISHED/ARCHIVED
4. assert root ACTIVE
5. assert no DRAFT exists
6. calculate next version number
7. insert new DRAFT
8. load source options ordered by sortOrder
9. create NEW option UUIDs
10. build oldOptionId -> newOptionId map
11. insert cloned options
12. load source correct-option mappings
13. remap to new option IDs
14. insert cloned correct-answer rows
15. commit

Rollback everything on failure.

10. CRITICAL sourceContentHash Semantics
---------------------------------------
The #001 design intended `sourceContentHash` for translation staleness of translatable/source content.

If the hash includes version-scoped option UUIDs, a pure clone would produce a different hash even though human-visible translatable content did not change.

That may incorrectly mark future translations stale.

Audit current #004 canonical hash implementation.

Preferred multilingual-safe rule:
`sourceContentHash` should cover translatable semantic content, NOT volatile version-specific option UUIDs.

Candidate canonical option content:
- code
- text
- mediaAssetId
- sortOrder

Exclude:
- option row UUID id

Correct-answer mappings should generally also be excluded from translation-source hash because correctness is not translated.

If current implementation includes option IDs:
fix it now and update tests, unless there is a documented reason not to.
