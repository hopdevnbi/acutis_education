11. Version Constraints
-----------------------
Required:

version_number > 0

Unique:
(question_id, version_number)

Filtered unique:
one DRAFT per question

CHECK status allowed:
DRAFT/PUBLISHED/ARCHIVED

CHECK question_type allowed:
SINGLE_CHOICE/MULTIPLE_CHOICE/TRUE_FALSE

CHECK difficulty:
NULL or EASY/MEDIUM/HARD

CHECK source_content_hash:
NULL or exactly 64 lowercase hex

CHECK publish timestamp consistency:
DRAFT -> published_at NULL
PUBLISHED/ARCHIVED -> published_at NOT NULL

If SQL Server filtered/check syntax has limitations, implement safely and document.

21. Correct Option Cross-Version Integrity
------------------------------------------
Important:
A DB FK on option_id alone does not guarantee option belongs to same question_version_id.

Audit options.

Preferred robust DB design:
make question_options have unique `(question_version_id, id)` and use composite FK:
(question_version_id, option_id)
→ question_options(question_version_id, id)

If SQL Server/TypeORM migration supports cleanly, implement this.

This prevents a correct-answer row referencing an option from another version.

Do not defer this if easy.
