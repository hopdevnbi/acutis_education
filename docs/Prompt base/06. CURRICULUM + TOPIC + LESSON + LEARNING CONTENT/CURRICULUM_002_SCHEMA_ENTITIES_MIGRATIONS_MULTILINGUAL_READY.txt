5. Multilingual Foundation — REQUIRED
-------------------------------------
CURRICULUM #001 deferred locale fields because i18n was not yet in roadmap.

That roadmap changed.

We do NOT build translation tables yet.

But source content needs language identity from day one.

Therefore add:

curriculums.source_locale

and/or curriculum_versions.source_locale

Audit exact placement.

Preferred:
`curriculums.source_locale` = canonical language of curriculum lineage.

Reason:
all versions of a curriculum normally share source language.

If future version could change source language, version-level sourceLocale would be needed.

Choose the least surprising model and document.

Strong recommendation:
- `curriculums.source_locale` required
- BCP 47 string
- default `vi-VN` only if project conventions allow explicit application default
- DO NOT DB-default silently if app-generated values are preferred

6. Locale Storage

Locale codes are ASCII identifiers, so varchar is correct.

18. canonical_lesson_key
-----------------------
uniqueidentifier NOT NULL

Application-generated UUID v4.

Do NOT DB-generate.

This key is stable across version clones.

It is not globally unique per row because the same canonical key intentionally appears in multiple curriculum versions.

Therefore:
DO NOT create UNIQUE(canonical_lesson_key).

Create index:
IX_lessons_canonical_lesson_key
