5. Delivery Ownership
---------------------
Published curriculum resolution is driven by operational context:

Class:
(parishId, academicYearId, catechismLevelId)
→ CurriculumAssignment
→ published curriculumVersion
→ tree

Enrollment:
enrollment.classId
→ ClassSnapshot triple
→ assignment
→ published version
→ tree

Therefore operational orchestration should live downstream of Curriculum.

6. Class Delivery Route
-----------------------
Implement:

GET /api/v1/classes/:classId/curriculum-tree

Permission:
curricula.read

Flow:
1. authenticate
2. load ClassSnapshot
3. assert caller can read class:
   - SUPER_ADMIN
   - PARISH_ADMIN active parish membership
   - CATECHIST active class assignment
   - PARENT only if linked child currently/relevantly enrolled in class
   - STUDENT only if own linked student profile enrolled in class
4. resolve curriculum assignment from class triple
5. assignment target must be PUBLISHED
6. return published tree only

No draft/current admin shortcuts.

7. Enrollment Delivery Route
----------------------------
Implement:

GET /api/v1/enrollments/:enrollmentId/curriculum-tree

Permission:
curricula.read

Flow:
1. load enrollment snapshot
2. assert caller can read enrollment
3. resolve class snapshot/triple
4. resolve assignment
5. return PUBLISHED tree only

Parent:
must be guardian-linked to enrollment student.

Student:
must match user-linked student identity.

Catechist:
must be assigned to enrollment class.

9. Lesson Access Context
------------------------
A learner must not obtain published content merely by knowing lessonId.

Resolve:
lesson
→ curriculumVersion
→ curriculum root
→ assignment(s)
→ accessible class/enrollment evidence

Access must prove the caller is connected to a class/enrollment using that exact published version.

10. Published Content Scope
---------------------------
For a given lessonId:

- version status must be PUBLISHED
- lesson must belong to that version
- assignment must target that exact version
- caller must have access to a class/enrollment whose triple maps to that assignment

This prevents:
- random published curriculum enumeration
- cross-parish lesson access
- stale historical version access unless explicitly allowed

11. Historical Published Version Policy
---------------------------------------
Important:
A previous version may become ARCHIVED when superseded.

Learner delivery should normally use ONLY the assignment's current target version.

If class/year assignment points to an ARCHIVED version due policy mismatch:
treat as invalid configuration or explicit historical admin path, not learner delivery.

Do not silently serve arbitrary ARCHIVED content.

12. Catechist Scope
-------------------
CATECHIST can read:
- assigned class curriculum tree
- published lesson content for curriculum assigned to that class

Cannot:
- read other classes
- read arbitrary parish curriculum via admin routes unless separately parish-admin
- read draft content

13. Parent Scope
----------------
PARENT can read:
- curriculum tree for linked child's enrollment/class
- published lesson content reachable through that child/class assignment

Cannot:
- list parish curricula
- read another child's class
- read arbitrary lesson by ID

Use ACTIVE guardian link only.
