PART B — HARDEN EXISTING FAMILY PORTAL CONTRACT
==================================================

B1. RBAC model
--------------
Do NOT add `family-portal.read`.

Reuse existing domain permissions.

Permission is NOT scope.

Catechist:
actor must be a valid Catechist portal actor.

Parent:
actor must be a valid Parent portal actor.

Relationship scope remains authoritative.

B2. Catechist scope
-------------------
Verify/fix:

- context uses active/current assigned classes only
- class list uses assigned classes only
- roster checks assignment BEFORE loading learner data
- no parish-wide escalation
- no client-controlled actor/user ID
- no admin fallback

Catechist scope source must remain owning-domain public services.

B3. Parent scope
---------------
Verify/fix:

- ACTIVE guardian links only
- ACTIVE enrollments only
- progress loads enrollment first
- studentId is derived server-side
- guardian relationship checked before Learning Progress composition
- no class-wide Parent aggregate
- no arbitrary child/student scope from client

B4. Admin impersonation
-----------------------
SUPER_ADMIN and PARISH_ADMIN must NOT automatically gain:

/me/catechist/*
/me/parent/*

These are actor-specific portal routes.

Admins use existing admin/domain routes.

B5. Cross-actor denial
----------------------
Verify all:

PARENT:
- parent routes yes
- catechist routes 403
- class-wide aggregate denied
- exam attempt denied

CATECHIST:
- assigned catechist routes yes
- parent routes 403
- learner exam attempt denied

STUDENT:
- parent portal 403
- catechist portal 403

PARISH_ADMIN:
- no portal impersonation

SUPER_ADMIN:
- no portal impersonation

B7. DTO ownership
-----------------
All controller responses must use FamilyPortal-owned DTOs.

Do not directly expose:
- TypeORM entities
- owning-domain entities
- owning-domain internal DTOs

Public service snapshots may be composed internally, but map to portal DTOs before HTTP response.

B8. Error contract
------------------
Normalize:

400
- malformed UUID
- invalid pagination/query

401
- unauthenticated

403
- wrong actor
- foreign enrollment
- unassigned class
- relationship denial

404
- truly unknown enrollment/class where safe and consistent

Expected:
unknown enrollment => 404
existing foreign enrollment => 403
unassigned class => 403

No raw DB errors.

-------------
Catechist class list:
- page
- limit
- max 50

Catechist roster:
- reuse Learning Progress bounds

Parent children:
- unpaginated MVP accepted because guardian count is bounded
- document this assumption

Verify stable pagination metadata:
page
limit
total
items

B10. Deterministic sorting
--------------------------
Ensure deterministic sorting for:

- context parishIds
- catechist classes
- roster rows
- parent children
- active enrollments within each child

Do not rely on implicit database order.

Use a stable business ordering already available.
If no product ordering exists, choose deterministic ID/name ordering and document it.

B11. N+1 verification
---------------------
Re-prove:

Catechist roster:
<= 5 orchestration-level calls

Expected:
1 scope/access

1 Exam batch
1 Student batch
1 Enrollment batch if needed

Parent children:
<= 4 bounded calls

Expected:

1 active enrollment batch
1 student batch
1 class batch

Parent progress:
bounded enrollment/guardian resolution + one LearningProgress composition

Do not call public domain service once per learner/child if a batch method exists.
