2. Why this module exists
-------------------------
Practice already has practice-specific progress:
- sessionsCompleted
- firstAttemptAccuracy
- finalAccuracy
- review metrics
- class Practice progress

Learning Progress must NOT duplicate that.

Learning Progress should represent the learner's broader educational progress across:
- enrollment
- curriculum
- curriculum version/assignment
- lesson/topic learning
- Practice outcomes
- future Exam outcomes

It should become an aggregation/read-model domain, not a god module.

18. Read Model vs Persistence
-----------------------------
This is the main #001 decision.

Option A:
Pure read aggregation from CurriculumDelivery + Practice.

Pros:
- no duplicated data
- simpler consistency
- faster implementation

Cons:
- cross-module read fanout
- future microservice latency
- harder historical snapshot if sources evolve

Option B:
LearningProgress-owned projection tables updated by domain events.

Pros:
- fast reads
- extraction-friendly
- historical stability

Cons:
- event consistency complexity
- duplication
- more schema/work

Option C:
Hybrid:
minimal persisted learner lesson progress + aggregate Practice on demand.

Audit and choose.
