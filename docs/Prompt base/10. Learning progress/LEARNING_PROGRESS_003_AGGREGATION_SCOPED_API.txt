Response concept:

  filters,
  learning: {
    curriculumId,
    assignedCurriculumVersionId,
    lessonsAssigned,
    lessonsStarted,
    lessonsCompleted,
    completionRatio
  },
  lessons: [
    { canonicalLessonKey, status, startedAt, completedAt }
  ],
  practice: {
    standard: {...},
    review: {...},
    lastPracticedAt
  },
  exam: null,
  lastLearningActivityAt
}

Learning Dimension
------------------
For the enrollment's assigned curriculum tree:

lessonsAssigned:
count current assigned lesson canonical keys.

lessonsStarted:
count IN_PROGRESS or COMPLETED states for canonical keys in current assigned tree.

lessonsCompleted:
count COMPLETED states for keys in current assigned tree.

completionRatio:
lessonsCompleted / lessonsAssigned.

If denominator 0, follow existing project convention; otherwise return 0.

Version Carry-Forward
---------------------
Same canonicalLessonKey in a republished curriculum version:
existing progress counts.

If new version removes a lesson:
historical row remains persisted but is excluded from current denominator.

If new version adds a lesson:
new key appears NOT_STARTED and denominator increases.

Lesson-State Synthesis
----------------------
Enrollment GET should return all assigned lesson keys:
- existing row -> IN_PROGRESS/COMPLETED
- missing row -> NOT_STARTED

This lets FE/Mobile merge directly with CurriculumDelivery tree.

Class rows must NOT include full lesson arrays.

Curriculum Filter
-----------------
For ACTIVE enrollment/class:
if curriculumId supplied and mismatches assigned curriculum -> 422.

canonicalLessonKey requires curriculumId and must belong assigned tree.
