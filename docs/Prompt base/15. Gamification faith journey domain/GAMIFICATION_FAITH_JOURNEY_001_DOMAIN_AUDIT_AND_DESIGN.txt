PART B — DOMAIN PRINCIPLE
==================================================

This platform is catechism/faith education.

Gamification must support learning motivation without turning sacramental/spiritual life into a simplistic competitive score.

Design should distinguish:

GAME-LIKE REWARDS:
- points
- badges
- missions

FAITH JOURNEY:
- milestones
- progress markers
- achievements
- participation/history

Avoid:
- public ranking of spiritual worth
- “holiness score”
- competitive comparison of sacramental/spiritual status
- leaderboards by default

Required design principle:
POINTS ARE ENGAGEMENT REWARDS, NOT SPIRITUAL VALUE.

Document this explicitly.

==================================================
PART C — POINTS LEDGER
==================================================

Strong recommendation:
immutable ledger, not mutable points counter.

Candidate table:
`point_ledger_entries`

Each entry:
- id
- studentId
- enrollmentId nullable if context-specific
- parishId
- academicYearId nullable
- pointsDelta signed integer
- sourceType
- sourceId
- reasonCode
- descriptionKey / short label
- awardedByUserId nullable for automated rewards
- createdAt
- idempotencyKey / uniqueness key

Balance:
SUM(pointsDelta)

Do NOT make balance a manually edited canonical column unless cached projection is justified.

Support negative entries only if needed for corrections/reversals.

Required decision:
POINT MODEL = immutable ledger / mutable balance / hybrid
