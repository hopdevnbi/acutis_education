==================================================
PART H — MISSION CONTRIBUTION IDEMPOTENCY
==================================================

Critical.

`processed_reward_events` prevents the same source RewardEligibleEvent being processed twice globally.

Therefore mission progress increment for one event occurs at most once if mission update is in the same ingest transaction.

However:
one processed event can update multiple eligible missions.

Required:
- progress updates happen inside same transaction as receipt
- duplicate replay = no progress increment
- mission row unique (missionDefinitionId, studentId)
- currentCount capped at target
- completed mission never increments/reopens

No separate contribution table in MVP unless static inspection proves needed.
